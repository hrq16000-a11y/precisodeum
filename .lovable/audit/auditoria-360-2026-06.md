## DIMENSÃO 1 — Segurança / RLS

**Resultado:** 4 issues | 4 OK | nenhum P0

### [D1-01] P2 — 16 policies UPDATE sem WITH CHECK
- **Tabelas:** `agencies`, `jobs`, `whatsapp_templates`, `lead_alert_preferences`, `portfolio_albums`, `portfolio_photos`, `services`, `service_images`, `media`, `provider_page_settings`, `profile_change_suggestions`, `chat_conversations`, `chat_messages`.
- **Evidência:** `SELECT … FROM pg_policies WHERE cmd='UPDATE' AND with_check IS NULL` → 16 rows.
- **Problema:** `USING` filtra a linha; sem `WITH CHECK` o usuário pode trocar `user_id` para outro id e transferir ownership.
- **Recomendação:** Replicar `USING` em `WITH CHECK` para cada policy.

### [D1-02] P2 — `notify-auth-errors` sem auth
- **Arquivo:** `supabase/functions/notify-auth-errors/index.ts` + `supabase/config.toml` (`verify_jwt = false`).
- **Problema:** Endpoint público dispara e-mail ao admin — vetor de spam.
- **Recomendação:** Verificar header `x-supabase-webhook-secret` ou usar `validateCronRequest`.

### [D1-03] P2 — `check_registration_block` SECURITY DEFINER acessível a anon
- **Função:** `public.check_registration_block(_email, _whatsapp)`.
- **Problema:** Permite enumeração de PII por força bruta.
- **Recomendação:** Revogar EXECUTE de `anon`; aplicar rate-limit via `peek_auth_rate_limit`.

### [D1-04] P2 — `select('*')` em tabelas PII
- `src/pages/DashboardLeadsPage.tsx:256`
- `src/pages/AdminSponsorLeadsPage.tsx:46`

- **Recomendação:** Projeção explícita dos campos usados.
